Not via any file transfer, API, or database write — it's done by simulating a human typing on a terminal:

The sub grabs the currently active, already-connected Attachmate terminal session (ExtraSystem.ActiveSession) — someone/something else must have already logged into the mainframe before this runs
It checks which screen is currently showing by reading fixed text at fixed coordinates (e.g., "is the string at row 3, column 14 equal to M009000G?")
Based on that, it sends keystrokes to navigate menus: 13<Enter>, then 11<Enter>, then 1<Enter> — literally the same numeric menu options a human would type
Once on the right update screen, it moves the terminal cursor to exact coordinates (row 5 col 24; row 13 col 29; row 13 col 45) and types the part number, ETD date, and quantity into those exact spots
Sends <PF8> (a function key) to submit
Reads back a status message from a fixed screen location to determine success/failure
Repeats for the next part, using <PF11> to back out to the list

This is a screen-scraping automation, not an integration — it works only because someone built it to match this exact mainframe screen's exact layout, and it would break if that layout ever changed.
